# lhg-fs-frontend：前端实现方法论

> 目标：让 AI 生成的前端"不像 AI 生成的"——有真实产品的质感，没有模板味。
> 核心纪律：**先定设计语言，再写第一行代码；没有真实文案，宁可用中性占位也不编造。**

## 1. 何时使用

- 新建任何页面/组件前 → 加载本 skill
- 评审或重构存量页面时 → 用第 9 节自查清单逐项过
- 用户说"这个页面有点 AI 味，帮我改改"时 → 重点看第 3 节

## 2. 前置输入

动手前必须先有（来自 lhg-fs-memory 的 DESIGN.md）：

- 产品事实清单：产品名、一句话介绍、真实功能点、真实数据（没有就写"待补充"，不许编）
- 设计令牌：主色、辅助色、字体、圆角、间距基数
- 页面清单：要做哪几个页面，每个页面的核心内容

三者缺一不可。缺设计令牌时先定令牌，缺产品事实时先问用户要，**不许带着空白开工**。

## 3. 规则一：禁 AI 模板相

以下模式是 AI 生成 UI 的"指纹"，看到就改掉：

### 3.1 紫粉渐变
- 现象：`from-purple-500 to-pink-500` 之类的紫→粉渐变，配深色背景。
- 为什么禁：这是 2024-2025 年 AI 生成落地页最泛滥的配色，用户一眼就能认出"这是 AI 做的"。
- 怎么做：渐变只用在极小面积点缀（如按钮 hover 的一像素高光），且必须取自品牌色系；大面积背景用纯色或极淡的中性色。

### 3.2 霓虹暗黑
- 现象：纯黑背景 + 彩色发光阴影 + 玻璃拟态卡片三件套。
- 为什么禁：除非产品本身是开发者工具/游戏，否则这种风格与绝大多数真实业务不搭。
- 怎么做：默认浅色、中性底；深色只用在它有真实理由的地方（如代码展示、媒体播放）。

### 3.3 卡片套卡片
- 现象：页面全是圆角卡片，卡片里再套小卡片，信息层级靠"套娃"区分。
- 为什么禁：真实产品用"留白、字阶、分割线"做层级，套娃是偷懒。
- 怎么做：先问"这两块信息真的需要容器吗"，80% 的卡片可以删掉换成 spacing。

### 3.4 渐变标题字
- 现象：大标题用 `bg-clip-text` 做彩虹渐变字。
- 为什么禁：可读性差，且是模板味重灾区。
- 怎么做：标题用纯色，强调靠字重和字号对比。

### 3.5 Hero 三件套照搬
- 现象：居中大标题 + 一行副标题 + 两个按钮（"开始使用/了解更多"），下面跟三个特性卡片。
- 为什么禁：结构本身没错，但 AI 每次都生成一模一样的骨架。
- 怎么做：至少改一处结构——把标题左对齐、把特性做成横向时间线、把 CTA 融进产品截图，任选其一打破对称。

## 4. 规则二：内容诚实

这是红线，比审美更重要：

1. **不编造数字**："10 万用户""99% 好评"这类数字，没有真实来源就不写。可以用"内测中""即将上线"。
2. **不编造用户评价**：没有真实用户反馈，就不要写 testimonial 区；非要占位，写"用户评价（待补充）"并标灰。
3. **不编造客户 logo**：不要放没合作过的公司 logo。
4. **占位要诚实**：图片占位用中性灰块 + "图片待补充"，不要用假产品截图冒充。
5. **价格/政策写"待定"**：没定就写待定，不要编一个 99 元/月上去。

## 5. 规则三：设计令牌优先

1. 所有颜色、字体、字号、间距、圆角、阴影必须走设计令牌（CSS 变量或 Tailwind theme 扩展）。
2. **禁止在组件里硬编码十六进制色值**（`#3b82f6` 这种）。例外：设计令牌定义文件本身。
3. 新增颜色先问"令牌里有没有接近的"，没有才加令牌，不许就地发明。
4. 间距用 4px 基数的倍数（4/8/12/16/24/32…），不要出现 13px、27px 这种"手感值"。

## 6. 规则四：移动端优先

1. 先按 390px 宽度设计，再向桌面扩展——不要反过来。
2. 桌面端出现横向滚动条 = blocker，必须修。
3. 固定像素大宽度（如 `w-[1200px]`）禁止直接写在组件上，用 `max-w-*` + 响应式断点。
4. 触摸目标不小于 44px；悬停才出现的操作必须在移动端有替代入口。

## 7. 规则五：布局先行

1. 写代码前，先用 ASCII 草图把布局画出来（header/main/footer，每块写清内容），跟用户或自己确认一眼。
2. 草图示例：
```
+----------------------------------+
| 顶栏：Logo | 导航 | CTA按钮        |
+----------------------------------+
| Hero：左文案 / 右产品图            |
+----------------------------------+
| 特性：三列，每列 图标+标题+一句话  |
+----------------------------------+
```
3. 布局定稿后再写组件；布局大改时回到这一步重画，不要在代码里硬调。

## 8. 规则六：排版与动效

### 排版
- 字阶用固定档位（如 12/14/16/20/24/32/48），不要连续微调。
- 正文行高 1.6-1.75，标题行高 1.2-1.3。
- 一屏内字重不超过 3 种，颜色不超过 4 种。

### 动效
- 时长 150-300ms，缓动用 ease-out（进入）/ ease-in-out（常驻）；禁止 linear 生硬位移。
- 动效只用于"状态变化的解释"（展开、切换、反馈），不为装饰而动。
- 必须支持 `prefers-reduced-motion`：用户关了动效就全关。

### 可访问性基线
- 图片必有 alt；装饰图 alt 留空。
- 文字与背景对比度达到 WCAG AA（正文 4.5:1）。
- 可点击元素用原生 button/a，不用 div 套 onClick。
- 表单项有关联 label。

## 9. 七步实现流程

1. 读 DESIGN.md（令牌 + 页面清单）与 PRODUCT.md（产品事实）。
2. 画 ASCII 布局草图，确认。
3. 定/复用设计令牌（缺的先补进令牌文件）。
4. 按"静态结构 → 数据接入 → 交互 → 动效"顺序写组件。
5. 每完成一个页面，自查第 3-8 节规则。
6. 跑确定性审计脚本（见 lhg-fs-audit），修掉所有 blocker。
7. 截图（或描述）给用户确认后再继续下一个页面。

## 10. 自查清单（写完对照打勾）

- [ ] 无紫粉渐变/霓虹暗黑/卡片套娃/渐变标题字
- [ ] 无编造的数字、评价、客户 logo
- [ ] 零硬编码色值（令牌文件除外）
- [ ] 390px 下无横向滚动
- [ ] 图片有 alt，表单有 label
- [ ] 动效时长合理且支持 reduced-motion
- [ ] 无 lorem ipsum、无 TODO 残留、无 console.log

## 11. 反模式

- ❌ "先随便做一版，丑了再改"——第一版的骨架决定 80% 质感，返工更贵
- ❌ 用假数据把页面"填满"显得好看——诚实的中性占位比漂亮的假货好
- ❌ 每个页面发明一套新样式——一致性就是高级感

## 12. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 是否出现了第 3 节的模板相？→ 回炉重做对应部分。
2. 是否编造了任何产品事实？→ 立即改为诚实占位。
3. 是否有硬编码色值漏网？→ 补进令牌。
4. 移动端是否亲测（或等价检查）过？→ 没测不算完。

标准冒烟用例：用"个人作品集首页"走一遍本 skill，检查 7 条自查清单是否全绿。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-fullstack/issues，正文写清"输入 → 错误输出 → 期望输出"。
